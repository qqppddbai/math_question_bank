# 数学题库管理系统（MVP）

面向中学数学老师的**本地**题库工具：题目管理 · 搜索筛选 · 批量导入 · 手动组卷 · 试卷导出 · 学生错题档案。

- 纯本地运行，不联网、不登录、不上传
- 数据全部保存在 `data/` 目录，换电脑拷过去就能用
- 中文界面，KaTeX 实时渲染 LaTeX 公式

## 功能一览

| 模块 | 主要功能 |
|---|---|
| 🏠 首页概览 | 题库/试卷/学生/回收站统计，题型·难度·年级分布 |
| 📚 题目管理 | 新增、编辑、软删除；题干配图 / 解析配图 分别上传，并可**插到文字中间**；**保存/取消后自动滚回刚编辑的那道题** |

## 自测（改完代码想确认没弄坏东西时用）

```bash
python tools/verify/run.py
```

- 会把数据目录切到项目内的临时沙箱 `selftest_tmp/`，**不会动你真实的 `data/` 题库**；
- 自动建库、造几道带图的测试题，然后检查六组东西：
  1. 题目列表顺序稳定、按钮在卡片右侧、题干图和解析图渲染在正确位置；
  2. 编辑表单里「题干配图 / 解析配图」两组能各自上传、各自删除；
  3. 正文里的 `![[img:N]]` 定位标记：插到文字中间、宽度、序号越界、旧数据兼容、
     编辑器里的可复制标记与"未安置"提示；
  4. **改完立刻生效**：每个写操作（增/改/删/还原/批量加标签/批量删除/组卷取题）
     之后，读接口都必须马上返回新数据——防止再出现"要重启才生效"的问题；
  5. 导出 Word / HTML / Markdown 时图片各归各位，孤儿图片清理不会误伤解析图，
     也不会把导入草稿暂存目录里的图片当成孤儿；
  6. **导入的公式体检、逐条预览修改与覆盖导入**：坏的 LaTeX 能被挑出来、好的公式一条都不误报、
     自动修复后不再报错；草稿里改完题干会**按新题干重新查重**；上传的配图在确认入库前
     只落在暂存目录、入库后才转正且暂存目录被清空；重复题三种处理方式
     （跳过/覆盖/照样新增）都符合预期，覆盖时题目编号不变、原题配图不丢。
- 全过打印 `结果：全部通过 ✓`（退出码 0）；有失败会列出失败项（退出码 1）。

## 把配图插到文字中间（`![[img:N]]`）

题干和解析里都可以写标记来指定图片位置：

| 写法 | 效果 |
|---|---|
| `![[img]]` | 把该字段的**第 1 张**配图放在这个位置（只有一张图时最省事） |
| `![[img:2]]` | 第 2 张配图 |
| `![[img:2\|300]]` | 第 2 张配图，宽度指定为 300 像素 |
| 不写标记 | 图片排在文字**最后**（老题目就是这个行为，不用改） |

- 序号是**该字段内的序号**：题干里的 `![[img:1]]` 指题干配图的第 1 张，
  解析里的指解析配图的第 1 张，两者互不影响。序号可以省略（`![[img]]` = 第 1 张）。
- 同一张图可以重复引用；标了不存在的序号会在原位置给一行提示，不会静默消失。
- 正文里的图片**居中显示、下方不带任何图注**，默认宽度 **100 像素**；
  用 `![[img:1|300]]` 可以单独指定某张图的宽度，改全局默认值见
  `src/config.py` 的 `DEFAULT_IMAGE_WIDTH_PX`。
- 编辑器里每个缩略图下面都有可一键复制的标记，也可以展开
  「✍️ 不想手抄标记？用这里插入」选择"把哪张图放到第几段之后"。
- 导出的 Word / HTML / Markdown 同样按标记位置排图，也不带图注。

## 公式为什么会变成红字？（导入时的公式体检）

界面上的公式由 Streamlit 内置的 **KaTeX** 渲染。KaTeX 只实现了 LaTeX 的一个子集，
**它解析不了的公式会被渲染成一段红字**（`<span class="katex-error">`），
公式内容完全看不到。最典型的一种是从公式编辑器 / 转换工具复制出来的：

```
$f(x)=\left\{ \begin{array}{*{35}{l}} \text{ln}x,x>1 \\ -\text{ln}x,0<x<1 \end{array} \right.$
```

KaTeX 报 `Unknown column alignment: *` —— 它不支持 `*{35}{l}` 这种"重复列"写法，
改成 `\begin{array}{l}` 就能正常渲染。

**导入时（以及题目编辑器里）会自动做一次"公式体检"**，把这类问题提前挑出来：

| 会被提醒的写法 | 说明 |
|---|---|
| `\begin{array}{*{35}{l}}`、`p{2cm}`、`@{...}` 列格式 | KaTeX 不支持，可一键修复 |
| `\begin{eqnarray}` / `tabular` / `multline` 等 | KaTeX 根本没有这个环境 |
| 行内公式里用 `align` / `gather` / `equation` | 这些只能写在 `$$...$$` 里 |
| `\mbox` / `\qty` / `\label` / `\cline` / `\multicolumn` 等 | KaTeX 不认识的命令，会提示替代写法 |
| `\(...\)`、`\[...\]` | Streamlit 只认 `$...$` 和 `$$...$$` |
| `$` 没配对、`{}` 不配对、`\left` 与 `\right` 数量不等、`x^` 后面没内容 | 结构错误 |

- **只提醒，不阻断**：公式坏了题目本身还能用，导不导入由你决定；
- 公式问题会单独列一块（指标里的「公式有问题」、表格状态列的「🔴 公式红字」），
  点 **「🔧 自动修复公式」** 会把 KaTeX 不支持的写法换成等价写法，
  改完自动重新校验，确认无误再入库；
- 判断标准是**拿 KaTeX 自己核验过**的：支持的命令名清单由
  `src/utils/katex_commands.py` 提供（从 Streamlit 内置的 KaTeX 0.16.47 里抽取并逐条验证），
  检查逻辑在 `src/utils/latex_check.py`，自测里有一批正常公式专门用来防止误报。

## 批量导入：入库前先逐条看渲染效果、改错、加配图

导入流程分四步，**在看清楚之前一条都不会进题库**：

| 步骤 | 做什么 |
|---|---|
| ① 粘贴 / 上传 | 粘贴 JSON 数组，或上传 `.json` 文件（格式说明见页面里的「格式说明 / 示例」栏） |
| ② 校验结果 | 总条数 / 可入库 / 有问题 / 与库内重复 / 公式有问题，逐条给出状态与备注 |
| ③ 逐条预览与修改 | **左边改文字、右边实时渲染**，和入库后的显示完全一致（同一套渲染层）；可以加配图 |
| ④ 确认入库 | 选重复处理方式 → （覆盖时）备份 → 一键入库 |

**③ 里能做的事：**

- **实时预览**：题干、选项、答案、解析按题目卡片的样式渲染，公式走 KaTeX —— 入库后会是什么样，
  这里就是什么样。写错的公式会当场标成"会渲染成红字"，并给出「🔧 修复本条的公式」一键修好；
- **当场改文字**：题干 / 选项 / 答案 / 解析 / 题型 / 年级 / 难度 / 来源 / 知识点 / 标签都能改，
  不必回去重写 JSON；
- **改完自动重新查重**：这里判重用的是**改过之后**的题干。所以把题干改得跟库里某道题重复时，
  页面会立刻标出「⚠️ 重复」并给出题号 —— 覆盖模式不会改错题；
- **加配图**：分**题干配图**和**解析配图**两组上传。缩略图下方给出可复制的定位标记
  （只有一张图时是 `![[img]]`，多张是 `![[img:1]]`、`![[img:2]]`，要指定宽度写 `![[img:1|300]]`），
  把它粘到文字里想放图片的位置即可；**不写标记的图片会排在文字最后**；
- 改的内容**不会回写上面那个 JSON 文本框**（免得两边互相打架）。想改 JSON 就改完重新点
  「🔍 解析并预览」，那会**重建草稿**，之前在这里的修改会丢。

**配图什么时候真正存盘：** 上传的图片先放在 `data/images/_import_staging/` 暂存，
**点「确认入库」时才复制到正式图片目录**。所以取消导入、重新解析、直接关掉浏览器，
都不会在 `data/images/` 里留下一堆没人引用的垃圾文件；
万一真的留下了（比如程序被强杀），「⚙️ 系统设置 → 🧹 清理」里有兜底的一键清理入口。
孤儿图片扫描也会跳过这个暂存目录 —— 那里面的图不算孤儿。

## 导入时遇到重复题：跳过 / 覆盖 / 照样新增

导入前会按**题干内容**（忽略所有空格）在题库里查重。预览页给出三个选项：

| 选项 | 行为 |
|---|---|
| **跳过重复（推荐）** | 库里已有的不动，只导入新题 |
| **覆盖题库里的原题** | 用导入的内容改写库内那道题 |
| **照样新增一份** | 不管重复，直接再建一条（会产生重复题） |

覆盖的几个要点：

- **题目编号不变**：是原地改写，不是"删掉重建"，所以**试卷里的引用、学生错题关联都不会断**；
- **原题配图不会被清掉**：导入的 JSON 里没有图片信息，覆盖时保留原有的题干图 / 解析图；
- **不可撤销**：覆盖会直接改掉原题内容，回收站里没有它的旧版本。所以覆盖模式下
  默认勾选「覆盖前先做一次整库备份」，备份文件放在 `data/backups/`，可在「系统设置」里查看；
- 同一道题干在库里有多份时，只改写**编号最小**的那一份，其余保持原样（界面会列出来要改哪些）。

## 保存 / 取消后回到列表：位置不会丢

编辑题目保存后回到列表页，浏览器会把滚动条拉回顶部。如果刚改的题在第 15 道、第 8 页
或者很靠下的位置，就得重新翻半天才知道自己刚改的是哪一道。

现在保存成功后，**列表自动滚回刚改的那道题所在的位置**，并给它描一圈绿边：

- **列表顺序、分页、筛选完全不变**，那道题还在它原来的位置上，只是页面滚过去了；
- 点「⬅️ 返回列表」或「取消」退出编辑页，同样会回到刚才在改的那一道；
- **新增**的题是个例外：它编号最大、必然排在最后一页，所以保存后会自动翻到那一页再定位；
- 定位只做一次：之后正常浏览、翻页、编辑别的题，都不会再被拽回去；
- 如果改完题干/年级后它不再符合当前筛选条件（这一页里没有它了），页面会提示一句
  「刚保存的题目 #N 不在当前筛选条件下」，不会默默无反应。

实现说明：Streamlit 没有官方的「滚动到某个元素」接口，所以用 `components.html` 里的
一小段脚本，让同源 iframe 去调用父页面的 `element.scrollIntoView()`。可行性来自
Streamlit 给组件 iframe 的 sandbox 里带了 `allow-same-origin`
（见 `streamlit/static/static/js/IFrameUtil.*.js`）。绿边用的是 `outline`
（不参与布局，不会让卡片抖动）。这段行为已用 Playwright + Chromium 在真浏览器里验证过：
内容高 4122px、视口 800px 的列表里滚到第 15 题（scrollTop 2558），保存回来后
scrollTop 2698、第 15 题仍落在屏幕中间，没有被拉回顶部。
